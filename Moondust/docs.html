Documentation

Moondust is a tiny package manager for Lua. You drop in one file, and moondust("author/package") downloads a package the first time and loads it like require.

Install

Download moondust.lua and put it next to your script:

curl -O https://thegamingmahi.github.io/Moondust/moondust.lua

It works on Lua 5.1 to 5.5 and LuaJIT, and needs curl (already on macOS, Linux and Windows 10 and later). Moondust only handles pure Lua packages for now.

Using packages

Local (recommended)

local moondust = require("moondust")
local tf = moondust("thegamingmahi/tinyfiles")

tf.writefile("hello.txt", "Hi")

The first run downloads the package. Later runs load it from disk. You never give a file path.

No variable (the package sets its own globals)

Some packages, like TinyFiles, create global functions when they load, so you can just use them:

require("moondust")("thegamingmahi/tinyfiles")

wait(2)
writefile("hello.txt", "Hi")
print(readfile("hello.txt"))

Global moondust (many files)

Set it once in your main file, then call it from any other file without requiring it again:

-- main.lua
moondust = require("moondust")

-- any other file
local tf = moondust("thegamingmahi/tinyfiles")

From code

CallWhat it does
moondust("a/b")Load a package, downloading it if needed. moondust.use("a/b") is the same.
moondust.install("a/b")Download the latest version and make it the project’s current one.
moondust.update("a/b")Same as install. With no argument, updates every package in moondust.lock and returns a list of results.
moondust.list()Returns the installed packages (name, version, sha256, installed).
moondust.verify()Checks files against the lock. Returns the results and how many have a problem.
moondust.uninstall("a/b")Removes the package and its lock entry. Returns whether anything was removed.

Versions

moondust("thegamingmahi/tinyfiles")          -- the project's current version (latest on first use)
moondust("thegamingmahi/tinyfiles@1.0.0")    -- an exact version

The first time you use a package, Moondust picks the newest version and remembers it in moondust.lock. After that your project stays on that version, even when the author publishes a newer one, so your code never changes under you. To move to the newest version:

lua moondust.lua update thegamingmahi/tinyfiles

An exact version like @1.0.0 that isn’t the current one is saved next to it and doesn’t change the lock. Published versions can never be overwritten.

Command line

The same file works as a command:

CommandWhat it does
lua moondust.lua install author/packageDownload the latest version and record it in moondust.lock.
lua moondust.lua install author/package@1.0.0Same, for an exact version.
lua moondust.lua update author/packageSwitch one package to its newest version.
lua moondust.lua updateUpdate every package in moondust.lock.
lua moondust.lua listShow installed packages with their version and checksum.
lua moondust.lua verifyCheck every installed file against the lock. Exits with code 1 if anything is wrong.
lua moondust.lua uninstall author/packageRemove a package and its lock entry.
lua moondust.luaShow the help text.

Logging in and publishing from the command line are coming soon. For now, publish on the website.

Files Moondust creates

your-project/
├── moondust.lua                       the loader you downloaded
├── moondust.lock                      versions and checksums (commit this)
├── .luarc.json                        editor settings (see Editor autocomplete)
└── lua_modules/
    └── thegamingmahi/
        ├── tinyfiles.lua              the project's current version
        └── tinyfiles@1.0.0.lua        another exact version you asked for

moondust.lock has one line per package:

thegamingmahi/tinyfiles 1.0.0 sha256:66dd096ef15720e64e74562892f69a8fcd5cadcfa9bbeec72b9ed5a0b831f0e8

Publishing a package

  1. Put a moondust.json in the root of a public GitHub repo that you own.
  2. On the homepage, log in with GitHub and claim your username. You can do this once, and it can’t be changed.
  3. Paste your repo and press Publish.

Your package becomes username/name. Each version is pinned to your repo’s latest commit at that moment. To release an update, raise version in moondust.json and publish again. A version can only be published once. New versions can take a few minutes to show up everywhere.

moondust.json

{
  "name": "tinyfiles",
  "version": "1.0.0",
  "description": "Tiny Lua library for reading and writing files",
  "main": "tinyfiles.lua",
  "lua": ["5.1", "5.3", "5.4"]
}
FieldRequiredMeaning
nameyesLetters, numbers, - and _, up to 40 characters. The package is published as username/name.
versionyesThree numbers, like 1.0.0. Each version can only be published once.
mainyesThe one .lua file in the repo root that Moondust downloads, up to 512 KB.
descriptionnoShort text shown on the website, up to 200 characters.
luanoThe Lua versions it supports, from "5.1" to "5.5". Defaults to ["5.3"]. LÖVE games run Lua 5.1, so include "5.1" for them.

Checksums and safety

  • Every version is pinned to an exact commit, so a package can’t change after it’s published.
  • moondust.lock stores a SHA-256 checksum of each package it installs. If you download that version again (a fresh clone, a restored file), the download must match the checksum or it’s refused and deleted. Commit moondust.lock to git so your whole team gets the same files.
  • lua moondust.lua verify checks your installed files against the lock. Set MOONDUST_VERIFY=1 to check on every load (slower).
  • Checksums need sha256sum, shasum, openssl or certutil (all common), or LÖVE. Without one, Moondust warns and skips the check.
  • The registry doesn’t store a checksum yet, so your first download is trusted by its commit. Packages aren’t reviewed. Moondust runs code from the internet, so check what you install.

Editor autocomplete

On the first download, Moondust creates a small .luarc.json. Editors that use the Lua language server (the Lua extension for VS Code, Neovim, Zed) then treat moondust(...) like require:

local moondust = require("moondust")   -- keep this name
local tf = moondust("thegamingmahi/tinyfiles")
tf.   -- suggestions appear here
  • Functions that a package makes global, like wait() and writefile() in TinyFiles, autocomplete too.
  • It works when lua_modules is in .gitignore, and when moondust is a global.
  • It only recognizes the name moondust. local md = require("moondust") gets no suggestions.
  • If you already have a .luarc.json, Moondust leaves it alone and prints the settings to add. Reload your editor window once if suggestions don’t appear.

LÖVE

Use LÖVE 12 or newer. Moondust then uses LÖVE’s built-in https module instead of curl, and saves packages in the game’s save folder. Call it from love.load, because downloads pause the game. LÖVE runs LuaJIT (Lua 5.1), so packages must list "5.1". The command line and .luarc.json aren’t used in LÖVE.

function love.load()
  local moondust = require("moondust")
  tf = moondust("thegamingmahi/tinyfiles")
end
